# kkb — 日本株バックテスト基盤

過去の株価データを使って、売買ルールが本当に機能したのかを検証するツールです。

## 最初に読んでください

**これは「儲かるシステム」ではありません。** 儲かるかどうかを**お金を使う前に調べる道具**です。

投資戦略の世界では、頭の中で「良さそう」と思ったルールのほとんどが、過去データで
試すと負けます。このツールの一番の価値は、**損失を出す前に「そのアイデアはダメだ」と
教えてくれること**です。地味ですが、これが実際に一番お金を守ります。

また、ここで良い成績が出たからといって、将来も同じ結果になる保証はまったくありません。
理由は後述の「過剰最適化」を読んでください。

## セットアップ

### 1. Pythonを用意する

Python 3.10以降が必要です。入っているか確認します。

```bash
python3 --version
```

`command not found` と出たら [python.org](https://www.python.org/downloads/) からインストールしてください。

### 2. このリポジトリを取得する

```bash
git clone https://github.com/munimuniyaeba1995-glitch/kkb.git
cd kkb
```

### 3. 仮想環境を作ってライブラリを入れる

仮想環境とは「このプロジェクト専用のPython置き場」です。
パソコン全体の環境を汚さずに済むので、作っておくのが安全です。

```bash
python3 -m venv .venv

# 有効化（Mac / Linux）
source .venv/bin/activate

# 有効化（Windows）
.venv\Scripts\activate

# ライブラリのインストール
pip install -r requirements.txt
```

先頭に `(.venv)` と表示されれば成功です。
次回以降も、使う前に「有効化」のコマンドだけ実行してください。

## 使ってみる

### まず動かす

```bash
python run.py --code 7203 --strategy smacross
```

トヨタ自動車（7203）を、移動平均クロス戦略で 2020年〜現在まで検証します。

### 全戦略を比較する

```bash
python run.py --code 7203 --strategy all
```

### グラフも出す

```bash
python run.py --code 6758 --strategy smacross --plot
```

`results/` フォルダにPNG画像が保存されます。

### インターネットが無い / データ取得に失敗する場合

```bash
python run.py --code 7203 --source sample
```

乱数で作った練習用データで動きます。**実在の値動きではない**ので成績に意味はありませんが、
ツールの動作確認や使い方の練習になります。

## よく使うオプション

| オプション | 意味 | 例 |
|---|---|---|
| `--code` | 証券コード | `--code 7203`（トヨタ） |

全オプションは `python run.py --help` で見られます。

## 結果の読み方

出力される数字は、**この順番**で見てください。

### ① 最大ドローダウン（一番大事）

過去最高値からの最大の落ち込みです。`-40%` なら、
**資産が一時的に4割減る時期を耐え抜く必要がある**という意味です。

年率リターンが高くても、ドローダウンが深い戦略は実際には続きません。
たいていの人はそこで怖くなって売ってしまい、損だけが確定するからです。
自分が耐えられる数字かどうかで判断してください。

### ② 買い持ちとの差（次に大事）

`buyhold`（最初に買って持ち続けるだけ）に**勝てていない戦略には価値がありません**。
売買を繰り返した分だけ手数料を払って、成績を悪くしているだけです。

複雑な戦略が単純な買い持ちに負けるのは、まったく珍しいことではありません。
むしろそれが普通です。

### ③ プロフィットファクター (PF)

総利益 ÷ 総損失。`1.0` 未満なら赤字です。
`1.3` を超えれば一応の目安になりますが、取引回数が少ないと当てになりません。

### ④ 取引回数

`10回未満`の結果は**ほぼ偶然**だと思ってください。
コインを10回投げて7回表が出ても、そのコインが特別だとは言えないのと同じです。

### 勝率は当てになりません

勝率90%でも、1回の負けで全部失う戦略は破産します。
勝率30%でも、勝つときに大きく勝てば儲かります。勝率単体では何も判断できません。

## このツールが現実に合わせている4つのこと

バックテストは、作り方を間違えると**実際にはあり得ない好成績**が簡単に出てしまいます。
このツールは以下を守っています。

### 1. 未来を見ない（最重要）

「その日の終値を見て、その日の終値で買う」バックテストは間違いです。
終値を見た瞬間には、その日の取引はもう終わっています。

このツールは **t日の終値で判断 → t+1日の始値で約定** としています。
これは実際にできる取引です。この違いだけで成績は劇的に変わります。

この仕組みが壊れていないことは `tests/test_backtest.py` の
`test_no_lookahead_bias` で機械的に検証しています。

### 2. 単元株（100株単位）で買う

日本株はふつう100株単位です。「資金ぴったり使って1.7株買う」はできません。

### 3. 手数料とスリッページを引く

売買のたびにコストがかかります。往復コストを無視すると、
実際には負ける戦略が勝っているように見えます。

### 4. 株式分割を調整する

分割があった日に株価が半分になるのを「暴落」と誤認しないよう補正しています。

## 過剰最適化という罠

このツールを使い始めると、必ずこうしたくなります。

> 「`--short 5 --long 25` はイマイチだな。`--short 7 --long 32` にしたら成績が上がった！これだ！」

**これが一番危険な瞬間です。**

同じ過去データに対して何十通りも設定を試せば、そのデータにだけ都合よく当てはまる数字は
必ず見つかります。しかしそれは、**過去を言い当てただけ**であって、未来を予測する力とは
まったく別物です。

対策として、最低限これはやってください。

1. **期間を分けて検証する** — 例えば 2015〜2020年で設定を決めたら、
   その設定のまま 2021〜2024年で試す。後半で成績が崩れるなら、それは過剰最適化です。
2. **複数の銘柄で試す** — 1銘柄でしか通用しないルールは、ただの偶然です。
3. **試した回数を数える** — 50通り試して見つけた「最良の設定」は、
   ほぼ確実に見せかけです。

## 次のステップ

このツールで検証したあと、実際のお金を使うまでの順番です。**飛ばさないでください。**

1. **バックテスト**（今ここ）— 過去データで検証する
2. **期間外検証** — 設定を決めるのに使っていない期間で試す
3. **ペーパートレード** — 仮想の資金で、リアルタイムに数ヶ月動かす
4. **少額の実弾** — 失っても生活に影響のない金額で始める

3を飛ばして4に行くと、たいてい授業料を払うことになります。

## ファイル構成

```
kkb/
├── run.py                    実行コマンド（ここから起動する）
├── requirements.txt          必要なライブラリ
├── kabu/
│   ├── data.py               株価データの取得とキャッシュ
│   ├── indicators.py         移動平均、RSIなどの指標
│   ├── strategies.py         売買戦略（ここに自分の戦略を追加する）
│   ├── backtest.py           バックテストエンジン（心臓部）
│   ├── metrics.py            成績の集計と表示
│   └── plot.py               グラフ描画
└── tests/
    └── test_backtest.py      エンジンが正しいかの検証
```

### 自分の戦略を追加するには

`kabu/strategies.py` に `Strategy` を継承したクラスを足し、
`REGISTRY` に登録するだけです。既存の `SMACross` が一番短い見本になります。

やることは「各日について、株を持ちたいなら1、持ちたくないなら0を返す」だけ。
いくらで何株買うかはエンジン側が処理します。
