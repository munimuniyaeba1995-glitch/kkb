# 設計書 — ASHEN CROWN

## 1. 技術選定

| 候補 | 費用 | 3D性能 | 初心者向け | AIとの共同開発 | 判定 |
|---|---|---|---|---|---|
| **Godot 4.3 + GDScript** | 完全無料（MITライセンス、売上ロイヤリティなし） | 中〜高（Forward+、影、フォグ、グロー） | ◎ 本体100MB弱・インストール不要・言語がPythonに近い | ◎ シーン・スクリプトが全てテキストで差分管理しやすい／ヘッドレス自動テスト可 | **採用** |
| Unity 6 | 個人は無料（収益条件あり） | 高 | ○ 情報は多いがエディタ必須・重い | △ シーンがバイナリ寄り、CLIテストが重い | 不採用 |
| Unreal Engine 5 | 無料（売上100万ドル超で5%） | 最高 | △ 要求スペック・容量が大きくC++/Blueprint | △ Blueprintはテキスト化できない | 不採用 |

**選定理由**: 無料・軽量・ライセンスが最も単純で、初心者のPCでも動き、AIがコードとテストを全部テキストで扱えるため。
Android / iOS / Windows へ同じコードで書き出せる。

**2026-10 再検討（スマホ優先方針）**: Unity + URP も候補にしたが、開発用クラウド環境では Unity の
ダウンロード・ライセンス認証ができず、AIが起動・テスト・ビルドを自動実行できないため、
オーナー判断で Godot を継続。描画方式を **Mobile レンダラー**に変更した（Vulkan非対応端末は自動でOpenGLに切替）。
同じ構成（Godot 4.x / GDScript / Mobile）で最後まで開発する。

### 必要なソフトウェア
| ソフト | 用途 | 必須 |
|---|---|---|
| Godot 4.3 Standard（Windows 64-bit） | 開発・実行 | 必須 |
| Git for Windows | 変更履歴・復旧 | 推奨 |
| Blender（無料） | 本格的な3Dモデル作成（フェーズ9以降） | 任意 |

### 動作要件（目安）
**スマートフォン**: Android 7.0 以上・64bit（arm64）・メモリ3GB以上を想定。横画面固定。
iOS は Mac + Xcode が必要（README参照）。

**PC**
- Windows 10/11 64bit、メモリ8GB
- Vulkan対応GPU（2016年以降の多くのGPU/内蔵GPU）。Vulkanが使えない場合、Godot 4.3は自動でOpenGLに切り替わる。
  それでも起動しない場合は `project.godot` の描画方式を「Compatibility」に変更する。

## 2. 試作版（v0.1）の仕様

### プレイヤー
- HP 300 / スタミナ 100（回復 40/秒、使用後0.6秒は回復しない。0になると1.3秒）
- 弱攻撃3連撃 28→30→38、強攻撃 62（スタミナ 14/14/16/28）。攻撃後の硬直中に先行入力でコンボ
- 回避: スタミナ18、0.6秒、**開始0.03〜0.4秒が無敵**
- ガード: 正面の攻撃をダメージ15%に軽減、ダメージ×0.9のスタミナを消費。足りないとガードブレイク（大きく怯む）
- 回復薬「灰硝子の小瓶」: 初期3個、HP+140、使用中は移動が遅く、途中で被弾すると無駄になる
- ロックオン: 20m以内でカメラ正面に近い敵。28m離れるか撃破で解除

### 攻撃の作り（全キャラ共通）
`AttackData` = 予備動作(windup) → 判定(active) → 硬直(recovery)。
- 予備動作中は武器と目が赤く光る（見てから避けられる合図）
- 予備動作の前半（tracking）だけ相手に向き直り、後半は向きが固定 → 横・後ろに回り込めば避けられる
- 判定は**球形の物理クエリ**を毎フレーム出し、開始位置→終了位置へ動かして「振り」を表現。1回の攻撃で同じ相手に2回は当たらない
- 強靭度（poise）: 削り切ると怯む。雑魚20 / 強敵55 / ボス160

### 敵
| 名前 | HP | 残灰 | 攻撃パターン |
|---|---|---|---|
| 灰憑きの兵（雑魚） | 90 | 60 | 斬りつけ（近）、突進突き（中） |
| 黒鉄の処刑人（強敵） | 340 | 400 | 3連撃（確率で継続）、突進突き（中〜遠）、溜め振り下ろし（ディレイ） |
| 灰冠の守護者 ヴォルグレイン（ボス） | 1800 | 5000 | 薙ぎ払い・踏みつけ衝撃波（近）、叩きつけ（中）、跳躍攻撃（遠）。HP50%で第2形態（速度×1.25、予備動作×0.85、返し斬り追加） |

### 死亡・チェックポイントのルール
- 死亡 → 3.5秒後に最後に休息した篝火で復活。HP・スタミナ・回復薬は全回復、敵はすべて再配置
- 所持残灰は「最後に立っていた安全な地点」に落ちる。触れると全額回収
- **回収前に再び死亡すると、前回の落とし物は消滅し、今回の所持分が新たに落ちる**
- 撃破したボス、開けた宝箱、壊した隠し壁は復活しない
- 篝火で休息しても同じ処理（敵の再配置）が起きる

### マップ（エリア1「灰降る廃都・外縁」）
廃墟の前庭（開始・篝火・雑魚2・宝箱・隠し通路）→ 崩れた回廊（雑魚2）→ 処刑場跡（強敵・雑魚2・枯れ木の森）→ 篝火2 → 王冠の間（ボス、入ると霧の門が閉じる）

## 3. スマートフォン対応とPC展開の設計

### 機能の分離（プラットフォーム依存はここだけ）
| 機能 | ファイル | PC/スマホの違い |
|---|---|---|
| 入力 | `autoload/input_setup.gd`（アクション定義・移動の合成）、`ui/touch_controls.gd`（タッチ） | タッチUIは同じアクションを押すだけ。ゲーム本体は入力の種類を知らない |
| 端末設定・判定 | `autoload/game_settings.gd` | `is_mobile()` で初期値（画質・タッチUI）を決める。プラットフォーム判定はここに集約 |
| カメラ | `actors/camera_rig.gd` | マウス・右スティック・タッチのドラッグを `add_look()` で同じように受ける |
| 戦闘 | `combat/attack_data.gd`、`actors/actor.gd` | 共通 |
| キャラクター | `actors/player.gd`、`actors/character_rig.gd` | 共通 |
| 敵AI | `enemies/*` | 共通 |
| UI | `ui/hud.gd` | タッチ時はボスゲージを上、残灰を左上に移動（ボタン領域を避ける） |
| セーブ | `autoload/game_state.gd`（進行状態）／`user://settings.cfg`（端末設定） | 共通（セーブ/ロード本体はフェーズ9） |

### タッチ操作
- 左45%: 触れた場所に出る仮想スティック。指が外へ出たら中心が追従
- 右側: 空き部分のドラッグでカメラ。ボタンはマルチタッチ対応（指ごとに担当を記録）
- ボタンは720p基準の配置を画面の高さで拡大縮小。ノッチ（セーフエリア）の分だけ内側に寄せる
- アプリが裏に回ったら全ボタンを離した扱いにする（押しっぱなし防止）

### 画質プリセット（ポーズメニューで切替、端末に保存）
| 項目 | 低 | 中（スマホ初期値） | 高（PC初期値） |
|---|---|---|---|
| 3D解像度 | 60% | 80% | 100% |
| アンチエイリアス | なし | FXAA | MSAA 2x |
| 月光の影 | なし | 2分割・50m | 2分割・80m |
| 点光源の影 | なし | なし | あり |
| グロー（発光のにじみ） | なし | あり | あり |
| 舞う灰の粒子 | 40 | 110 | 220 |
| FPS上限 | 30 | 60 | 無制限（垂直同期） |

### 描画負荷の計測値（開発環境のソフトウェア描画、開始地点の視点）
| | 描画命令 | ポリゴン |
|---|---|---|
| 最適化前（高） | 約600 | 約55万 |
| 最適化後（高 / 中 / 低） | 約390〜435 / 320〜380 / 195〜240 | 約3.3〜3.7万 / 2.5〜2.9万 / 1.2〜1.5万 |

最適化内容: 球・円柱などの分割数削減、小物の描画距離（55m）と壁の描画距離（110m）、カメラの描画距離140m、
遠くの灯りのフェード、「低」で影を切る。※実機のFPS・メモリは未計測（フェーズ10）。

### 素材のライセンス方針
- 使ってよい: **CC0**（クレジット不要・商用可）、**CC-BY**（クレジット表記で商用可）、MIT/Apache等
- 使わない: 非商用限定（CC-BY-NC）、改変禁止（ND）、ライセンス不明のもの
- 導入時に `docs/CREDITS.md` に「素材名・作者・入手元URL・ライセンス・商用可否」を記録する
- 現在の外部素材: なし（Godot本体 MIT。クラウド用署名ツールの apksig は Apache-2.0、ゲームには含まれない）

## 4. フォルダ構成

```
project.godot            エンジン設定（自動読み込み・ウィンドウ）
scenes/                  起点となるシーン（title / main）
scripts/
  autoload/              常駐: 入力割り当て(InputSetup)、進行状態(GameState)、端末設定(GameSettings)
  actors/                Actor基底、プレイヤー、カメラ、仮の見た目(CharacterRig)
  combat/                AttackData（攻撃の定義）
  enemies/               Enemy基底AI、雑魚・強敵・ボス
  world/                 マップ生成、篝火、宝箱、隠し壁、残灰ドロップ、ボス部屋
  ui/                    HUD（ゲージ・ポーズ・死亡表示）、タッチ操作、タイトル
  fx/                    火花・舞う灰などの演出（スマホ向けにCPU粒子）
  game/                  main.gd（全体のつなぎ役）
tests/                   自動テスト・スクリーンショット撮影
tools/                   テスト実行・スクリーンショット・Androidビルド
  cloud_android/         クラウド環境専用のAPK署名ツール（Windowsでは使わない）
export_presets.cfg       書き出し設定（Android / Windows）
docs/                    設計書・ロードマップ
```

## 5. 開発上のリスクと回避方法

| リスク | 回避方法 |
|---|---|
| 規模が大きすぎて完成しない | 1エリア・敵3種の試作から始め、動く状態を保ったまま1フェーズずつ拡張 |
| 素材がなく見た目が貧弱 | 当面はプリミティブ形状。見た目は `CharacterRig` に閉じ込めてあり、後で無料モデル（CC0）に差し替え可能 |
| 素材のライセンス違反 | CC0 / CC-BY のみ使用し、出典を `docs/CREDITS.md` に記録（素材導入時に作成） |
| 既存作品に似すぎる | 名称・地名・敵・ストーリーはすべて独自。ゲームシステム（スタミナ制・回避・篝火型チェックポイント）は一般的なジャンル要素として扱う |
| 修正で別の機能が壊れる | 自動テスト22項目を毎回実行。Gitで各段階をコミットし、いつでも戻せる |
| PCによって起動しない | OpenGLへの自動切替。だめなら Compatibility 描画に変更 |
| 日本語が表示されない | Godot はOSの日本語フォントを自動で使う。表示崩れが出たら Noto Sans JP（OFL）を同梱する |
| スマホで重い・熱くなる | 画質プリセット、描画距離、低ポリゴン化、CPU粒子。性能表示で描画命令数を常に確認。実機で計測（フェーズ10） |
| タッチ操作が遊びにくい | 仮想スティック・大きめのボタン・押し判定を見た目の1.15倍に。実機テストで配置を調整 |
| iOSを後回しにすると対応が大変 | プラットフォーム依存を GameSettings / TouchControls に集約済み。Macが用意できた時点で書き出し |
| 難易度が理不尽になる | 全攻撃に予備動作と硬直を設定し、数値は `AttackData` で一括調整 |
